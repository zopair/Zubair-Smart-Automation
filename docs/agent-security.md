# نموذج أمان سير عمل الوكلاء

## ما يفعله الإصدار الحالي

مركز سير العمل الحالي منفّذ محلياً، ويشغّل خطوات محددة مسبقاً من سجل أدوات مسموح به. لا ينشئ شيفرة من وصف المستخدم، ولا يستخدم eval أو Function أو dynamic imports، ولا يتصل بمزود نموذج لغوي. لذلك فهو محرك تنفيذ مُقيّد، وليس وكيلاً لغوياً مستقلاً بعد.

## حدود التنفيذ

- كل خطوة تشير إلى toolId مسجل مسبقاً؛ أي معرف غير مسجل يُرفض.
- الخطة تُحفظ بحالة awaiting_approval ولا يمكن تنفيذها قبل اعتماد صريح.
- التنفيذ تسلسلي، ويتوقف عند أول خطوة فاشلة.
- المدخلات والمخرجات تُحوّل إلى JSON وتُقيّد أحجامها.
- سجل الأحداث محلي ومحدود بآخر 500 حدث.
- التنفيذ الحالي داخل تبويب المتصفح وعلى جهاز المستخدم؛ لا توجد ضمانات تزامن أو تشغيل خلفي متعدد المستخدمين.

## قبل إضافة موصل خارجي

1. تعريف نطاق صلاحيات مستقل لكل موصل.
2. فصل read عن write وdestructive، مع موافقة منفصلة للعمليات الحساسة.
3. عدم تمرير مفاتيح أو أسرار إلى واجهة المتصفح.
4. إضافة حدود وقت وحجم ومعدل تنفيذ، ومفاتيح idempotency للعمليات الخارجية.
5. التحقق من مخطط كل مدخل ومخرج وعدم الثقة في استجابات الطرف الثالث.
6. إضافة سجل تدقيق قابل للتصدير مع تنقيح البيانات الحساسة.
7. اختبار فشل الشبكة، انتهاء الصلاحية، التكرار، الإلغاء، واستعادة الحالة.
8. وضع الوسيط الخلفي في خدمة مستقلة قبل تمكين أدوات تتصل بالإنترنت أو تعدّل أنظمة خارجية.

## قيود معروفة

موافقة المستخدم الحالية تشمل الخطة كاملة، وليست موافقة لكل خطوة على حدة. لا تستخدم هذا الإصدار لعمليات مالية أو حذف بيانات أو تغييرات إنتاجية أو أي إجراء غير قابل للعكس. هذه العمليات تتطلب طبقة موافقات أدق وموصلات آمنة وخلفية موثوقة.
